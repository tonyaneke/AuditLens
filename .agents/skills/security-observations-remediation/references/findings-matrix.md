# AuditLens Security Findings Matrix (SEC-01 to SEC-07)

| ID | Severity | OWASP 2021 | Component | Observation | Attack Scenario / Impact | Evidence (observed) | Status of Proof | Recommended Remediation | Dev Owner |
|---|---|---|---|---|---|---|---|---|---|
| **SEC-01** | **Critical** | A01 Broken Access Control | `GET /api/data` | The endpoint returns the complete application dataset to any authenticated client regardless of role. The client-side sidebarAccess guard only hides sidebar links and route navigation; it does not restrict the data the API serves. | Any authenticated user (including the six action_owner accounts) can retrieve all 105 observations, all approvals, all fraud risks and the full Executive Assurance Brief by calling the API directly, bypassing the UI entirely. Confidentiality of the entire audit record is not enforced server-side. | `GET /api/data` as role=admin returns a single 527 KB JSON document containing keys: `audits`, `approvals(5)`, `fraudRisks(18)`, `processReviews(3)`, `extFindings(10)`, `iaSAList(12)`, `exco`, `notifications(115)`. sidebarAccess for this user is `[]`. Route guard is client-side only (all 9 routes return HTTP 200 server-side). | Observed directly. Cross-role read (as action_owner) To be confirmed by pentest. | Enforce authorization server-side. Filter the `/api/data` response by the caller's role and department. Do not rely on client-side route guards for data confidentiality. Ideally replace the single-document endpoint with scoped, per-resource endpoints. | Full-stack Sec |
| **SEC-02** | **Critical** | A01 Broken Access Control / A04 Insecure Design | `PUT /api/data` | Every save operation issues a full-document PUT containing the entire application state. There is no per-record write path, so per-record write authorization is structurally impossible under the current design. | If write authorization is not enforced per-record server-side, any authenticated user may be able to overwrite the entire audit record - including observation closure statuses, management responses, criticality ratings and the Board brief - in a single request. For a system of record feeding an Audit Committee, this is an integrity failure of the highest order. | Saving a single note issued `PUT /api/data` with the full 527 KB document, HTTP 200. No per-field or per-record endpoint exists. A `GET /api/data?meta=1` returns only `{updatedAt}`, indicating conflict detection was designed but is not enforced on write. | Whole-document PUT observed directly. Whether a low-privilege account can PUT a modified document To be confirmed by pentest (staging only). | Move to per-record write endpoints with server-side authorization on each. Enforce optimistic concurrency (If-Match / version token) to prevent last-write-wins overwrites. Until then, treat all write access as effectively admin-level. | Full-stack Sec |
| **SEC-03** | **High** | A07 Identification & Authentication Failures | `/api/auth/me` user object | The user object carries a `mustChangePassword` attribute in an application that authenticates via Microsoft Entra SSO. This implies a local username/password authentication path may exist alongside SSO. | If a local password login exists, it bypasses Entra conditional access, MFA and central identity governance. An attacker who obtains or guesses local credentials would evade every control the organisation applies at the Entra layer. If it is dead code, it misleads responders and widens the review surface. | `GET /api/auth/me` returns a user object including `mustChangePassword`. Primary sign-in flow is Microsoft SSO (OAuth2 authorize -> `/api/auth/callback` observed). | Field observed directly. Whether a working local login endpoint exists To be confirmed by pentest. | Confirm whether a local password authentication path is live. If so, disable it and enforce SSO-only, or bring it under conditional access and MFA. If it is dead code, remove the field and any associated endpoint. | Auth / Backend |
| **SEC-04** | **Medium** | A05 Security Misconfiguration | Application document response headers | The application HTML document is served without a standard security header set, and returns a permissive CORS header on the app shell. | Absent X-Frame-Options / CSP frame-ancestors, the application can be framed - enabling clickjacking against the approval and close-out workflows, where a tricked authenticated user could approve or close findings. Absent CSP, injected script has no containment. The ACAO wildcard on the shell is poor practice even though the API itself does not currently reflect it with credentials. | Response to `/tracker` contained none of: Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, Strict-Transport-Security. HSTS is present on `/api/*` but not on the document (inconsistent). Document returned `Access-Control-Allow-Origin: *`. API returned no ACAO and no Access-Control-Allow-Credentials. | Observed directly (header capture). | Add the standard security header set at the edge or middleware: a restrictive CSP with frame-ancestors 'none' (or 'self'), X-Frame-Options DENY, X-Content-Type-Options nosniff, Referrer-Policy strict-origin-when-cross-origin, and HSTS on all responses. Remove the ACAO wildcard from the application shell. | DevOps / Infra |
| **SEC-05** | **Medium** | A04 Insecure Design | `PUT /api/data` (availability / integrity) | Because all state lives in one document with last-write-wins semantics and no version guard, concurrent edits silently overwrite one another, and a single malformed or malicious PUT can corrupt or wipe the entire dataset. `lastBackup` exists in the payload but restore has not been verified. | Two users editing different observations concurrently will lose one set of changes with no warning. A single erroneous automated request against this endpoint (for example during a scanner run) could overwrite 105 observations and 72 closure records at once. This is precisely why penetration testing must target a staging clone with a verified restore point, not production. | Whole-document PUT with HTTP 200 and no concurrency token observed. `data.lastBackup` present; restore procedure not tested. | Availability impact reasoned from observed design. Not tested destructively (deliberately) on live data. | Add optimistic concurrency control and server-side schema validation on writes. Verify backup restore works and document RTO/RPO. Do not conduct active security testing against production. | Backend / Sec |
| **SEC-06** | **Low** | A09 Security Logging & Monitoring Failures | Audit log viewer | The 'Audit log' control in the profile menu is non-functional, so administrators have no in-app visibility of who changed what. Underlying note records do capture author and timestamp, so some data exists, but there is no accessible, tamper-evident trail. | Without an accessible audit trail, unauthorised or erroneous changes to the audit record cannot be detected or attributed after the fact - a monitoring gap in the very tool meant to evidence controls. Combined with SEC-02, changes may be both unrestricted and unobservable. | Clicking 'Audit log' produced no dialog, no route change and no network request. Observation notes correctly persist author and 'at' timestamp. | Observed directly. | Implement the audit log viewer backed by an append-only, tamper-evident change log covering all writes (who, what, before/after, when). Ensure logs are retained and access-controlled. | Frontend / Backend |
| **SEC-07** | **Info** | A05 Security Misconfiguration | Data payload composition | The directory endpoint embeds user photos as inline base64 data URIs, and `/api/data` returns a large monolithic payload on every page load, re-fetched multiple times. | Not a direct vulnerability, but the oversized, frequently re-fetched payload increases exposure of the full dataset across the network and to browser caches, and complicates rate-limiting and monitoring. Noted for defence-in-depth. | `/api/directory` 109 KB for 9 users (5 inline base64 photos, largest 25 KB). `/api/data` 527 KB fetched approx 8 times per page load; 40+ meta calls per load. | Observed directly. | Serve photos as access-controlled URLs. Reduce payload and fetch frequency (see performance finding QA-007). Consider caching and rate-limit headers on the API. | Backend / Perf |
